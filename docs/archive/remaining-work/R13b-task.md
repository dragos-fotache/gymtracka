## Storage and transactional design

Room14 is required. Add data-preserving 13→14 migration and exported schema; preserve all earlier snapshots and bundled v1 asset bytes. Prefer additive dedicated progress/acceptance tables so R13a evidence stays immutable:

- `sync_legacy_import_progress`: singleton id=1; `room_revision` INTEGER NOT NULL, `room_session_generation` INTEGER NOT NULL, `room_phase` TEXT NOT NULL, `operation_id` TEXT nullable (null only for signed-out fence), `active_consent_mutation_id` TEXT nullable. This is a current-lineage anchor, NOT independent session authority. It binds through the immutable singleton's origin/account. Valid captured R13a rows initialize it to their recorded PREPARING revision/generation/operation; blocked/no-journal rows do not gain one. No consent/receipt is fabricated by migration.
- `sync_legacy_import_acceptances`: `ordinal` INTEGER primary key, `mutation_id` TEXT NOT NULL UNIQUE, `batch_json` TEXT NOT NULL. No cascades into domain/outbox and no automatic cleanup. Receipt stores the validated complete accepted canonical batch using existing strict batch codec; mutation/order/request identity is bound to the immutable entry and original source. Do not store credentials, response headers or receipt timing as authority.

Read raw SQL scalar types/counts strictly; no coercive DAO success. Duplicate/orphan receipt/progress rows, malformed batch, entry/wrapper/source mismatch, a nonconsecutive accepted prefix, receipt with a still-retained request, missing request without receipt, mismatched account/origin/current anchor, missing progress or unknown phase fails closed. A receipt cannot be created from queue absence, cache/ledger contents, result summaries or arbitrary caller flags. Validate every original wrapper/record/affected root and its correspondence to frozen source even after the outbox/domain no longer exists.

For every recorded import acknowledged through the EXISTING accepted batch transaction:

1. Verify exact journal/entry/source/current authority and predecessor prefix, matching original frozen wrapper/sequence/type/root/generation and authorized active consent where applicable.
2. Apply canonical batch and metadata through accepted ack logic.
3. Persist one immutable receipt ONLY for validated accepted/original-accepted outcome, in the SAME transaction as exact head removal and canonical/metadata effects.
4. Recheck all affected receipt/evidence/remaining work/authority conditions after final SQL/trigger effects before commit. Any failure rolls back canonical/metadata/deletion/receipt together. Lost post-commit return rereads durable receipts; no duplicate receipt/recreated request.

Claim/send/preflight must refuse corrupted legacy evidence before HTTP. Existing generic PushStore/PreparedEngine paths cannot bypass settlement/consent checks just because the facade's policy is null. No legacy journal means existing ordinary ack/delivery behavior stays unchanged. Retained rejection/error state remains in original outbox; unsettled rejected requests never disappear or let dependent imports run.

Configured rest inputs remain the existing required nonnegative integer contract; a raw NULL configured rest is retained blocked source, never silently repaired. Nullable set weights/repetitions/recorded rest and optional custom metadata keep their represented semantics.

Before all settlement, associated source business rows remain original; allow only legitimate acknowledgment metadata/canonical progress, not arbitrary edits or missing source. After ALL receipts, snapshot/publication may legitimately replace/remove source domain rows, and later ordinary ACTIVE edits may differ; frozen source and exact entries/receipts remain validated and immutable. Do not compare post-publication live domain graph to capture forever. Repeated capture/read recovers original migration only; never generates another request.

Current-lineage progress advances atomically with existing Room authority transition writers (same-account reservation/finalization, private fence and completion), checking expected current anchor and origin/account, preserving original provenance. Capture initializes anchor atomically. Merely requiring generation >= capture is insufficient. Counter overflow, wrong tuple/trigger rewrite/count-zero fail without partial lineage advancement. Completion requires complete matching receipts/consent; clean RoomACTIVE/vaultPREPARED gap recovery and ordinary offline facade admission both revalidate retained evidence. Accepted migration can never become separate local-only data. Keep authority in existing facade/Room/vault machinery, not an alternate progress-based grant.
